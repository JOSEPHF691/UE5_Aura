## 1. 项目目标

使用现有角色、敌人、地下城、UI、音效与 Niagara 特效资产，完成一个基于 Unreal Engine 5.7 与 Gameplay Ability System（GAS）的可游玩 RPG Demo。

Demo 统一采用上帝视角：WASD 控制移动，按住鼠标右键旋转镜头，鼠标用于技能选点和方向确认。第三人称、全景俯瞰及 `V` 键切换已移除，避免同一套战斗被多套移动、光标和瞄准语义分割。

## 2. Demo 最小可交付范围

玩家以上帝视角进入地下城，使用基础攻击和技能击败数种敌人，获得恢复物品，并完成带最终 Boss 的短关卡。

建议首版内容：

- 1 个玩家角色。
- 3 个主动技能：火球、闪电/电击、范围碎片。
- 1 个基础攻击或法杖攻击。
- 3 类敌人：近战、远程、施法者。
- 1 个精英敌人或 Boss。
- 生命、法力、经验、等级、技能栏与冷却 UI。
- 1 个 10 至 15 分钟可完成的地下城关卡。

## 3. 技术架构

### 3.1 角色层

- `AAuraCharacterBase`：玩家与敌人的共同 GAS、属性和战斗能力基础。
- `AAuraCharacter`：玩家上帝视角相机及玩家专属表现。
- `AAuraEnemy`：敌人感知、AI、血条、受击和死亡表现。

### 3.2 GAS 层

- `UAuraAttributeSet`：生命、法力、力量、智力与护甲；`AAuraCharacter` 复制本轮等级、累计经验和局内强化，并通过 ASC 重建成长属性。
- Gameplay Ability：攻击、投射物、范围技能、冲刺及敌人技能。
- Gameplay Effect：初始化属性、伤害、消耗、冷却、Buff、Debuff 和恢复。
- Gameplay Tag：输入、技能、伤害类型、角色状态、冷却和阻断规则。
- Gameplay Cue：命中、施法、受击、死亡与状态特效。

### 3.3 上帝视角层

- `EAuraCameraMode` 仅保留 `TopDown / God View`。
- `AAuraCharacter` 负责 Spring Arm、Camera 和上帝视角参数。
- `AAuraPlayerController` 负责固定输入上下文、光标策略、移动语义与鼠标瞄准查询。
- `FAuraAimResult` 将鼠标命中转换为技能可消费的数据。
- Gameplay Ability 不直接访问摄像机，后续通过 Target Data 将客户端瞄准结果交给服务器验证。

### 3.4 输入层

计划建立以下 Enhanced Input 资产：

- `IA_Move`：Vector2D。
- `IA_Look`：Vector2D。
- `IA_PrimaryAttack`、`IA_Ability1` 至 `IA_Ability4`：Digital。
- `IMC_Common`：共享技能按键。
- `IMC_TopDown`：俯视移动、鼠标交互与选点。

## 5. 资产接入策略

- C++ 不硬编码具体 `/Game/...` 资产路径。
- 角色 Mesh、动画蓝图、技能蒙太奇、Niagara、音效和 UI 纹理由蓝图或 Data Asset 配置。
- 技能表现优先使用 Gameplay Cue，避免 Ability 内堆积特效逻辑。
- 玩家和敌人的数值采用 Gameplay Effect 或 Data Asset，便于调平衡。

当前资产目录已覆盖 `Characters`、`Enemies`、`Dungeon`、`Effects`、`Spells`、`Sounds`、`Pickups` 和 `UI`，足以支撑首版 Demo。

## 6. 风险与控制

- 多视角瞄准差异：所有技能统一消费目标数据，并在服务器侧限制最大距离和可见性。
- 动画骨架差异：先验证玩家和三类敌人的 Skeleton/Retarget，再批量接动画。
- 资产性能：对复杂 Niagara 和高成本材质建立可伸缩参数。
- 网络预测：移动由 CharacterMovement 处理；即时技能使用 GAS 预测，持续或范围技能采用服务器确认。
- 蓝图依赖失控：核心规则放 C++，资产引用和关卡编排留在蓝图/Data Asset。
